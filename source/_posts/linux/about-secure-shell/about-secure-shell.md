> SSH全称Secure Shell，是一种加密的网络传输协议，其目的是在不安全的网络中为网络服务提供安全的传输环境。

## 相关文件

SSH客户端配置、密钥生成及登录操作可能会在用户主目录下创建或使用`.ssh`目录，其中常见的文件包括：

- `config` : 配置文件，可以为远程主机配置host、登录端口、默认登录用户等，方便用户使用；
- `known_hosts` : 记录本机访问过的服务端所提供的host key，下次访问相同主机时会核对host key，如不匹配会发出警告；
- `id_rsa` : RSA密钥对的私钥文件；
- `id_rsa.pub` : RSA密钥对的公钥文件（其他密钥类型的文件名不同，例如`id_ed25519.pub`）；
- `authorized_keys` : 本机作为服务端所保存的已授权客户端的公钥；

## 密钥与身份认证

本文介绍SSH-2中常见的密码认证和公钥认证。两者都在SSH建立的加密通道中进行，但验证用户身份的方式不同：密码认证由服务端校验密码，公钥认证由客户端通过数字签名证明自己持有对应的私钥。

非对称密码算法使用一对相关联的公钥和私钥。加密和数字签名是不同的用途，并非所有算法都同时支持这两种用途：加密用于保护信息的机密性，数字签名则由私钥生成签名、公钥验证签名，用于验证消息来源及完整性，不能简单理解为“私钥编码、公钥解码”。私钥应由持有者妥善保管，公钥可以公开。

### 建立加密通道与验证服务端

在验证用户身份之前，客户端和服务端先协商算法并进行密钥交换，产生用于保护后续通信的对称密钥。服务端使用主机私钥对密钥交换相关数据签名，客户端验证签名，并检查对应的主机公钥是否可信。

客户端通常通过`~/.ssh/known_hosts`记录并校验服务端的主机公钥（host key）。首次连接未知主机时，客户端会显示主机公钥的指纹并询问是否信任；应通过可信渠道核对指纹后再接受。指纹是公钥的摘要，`known_hosts`保存的通常是主机公钥，而不只是指纹。后续连接时，如果主机公钥发生变化，客户端会根据配置发出警告或拒绝连接。

仅在首次连接时直接接受未知公钥，并不能确认对方就是真正的目标主机：如果此时连接被中间人拦截，客户端可能信任攻击者的主机公钥。主机身份校验是防止中间人攻击的重要环节。

### 密码认证的验证过程

1. 客户端和服务端完成上述密钥交换及主机身份校验，建立加密通道；
2. 客户端在该通道中发送用户名和密码，传输过程由协商得到的对称密钥保护，并不是直接使用服务端公钥加密密码；
3. 服务端收到请求后，通过相应的认证机制校验密码；
4. 服务端根据校验结果及认证策略决定是否允许登录。

### 公钥认证的验证过程

1. 客户端事先生成公钥和私钥，并把公钥追加到服务端目标用户的`~/.ssh/authorized_keys`文件中；
2. 客户端和服务端建立加密通道后，客户端提交用户名及准备使用的公钥信息；
3. 服务端检查该公钥是否被允许用于目标用户的认证。客户端可以先查询公钥是否可接受，再进行签名，也可以直接提交带签名的认证请求；
4. 客户端使用自己的私钥，对包含会话标识和认证请求内容的数据生成数字签名，并发送给服务端；
5. 服务端使用对应公钥验证签名，确认客户端持有相应私钥，且签名绑定的是当前会话中的认证请求；
6. 公钥授权检查和签名验证通过后，服务端根据认证策略允许登录，或要求继续完成其他认证。

整个过程中客户端不需要把私钥发送给服务端。这里描述的是公钥认证；SSH证书认证还涉及由证书颁发者签名的SSH证书，与直接把用户公钥加入`authorized_keys`的配置方式有所区别。

## 公钥认证的配置过程

- 客户端执行`ssh-keygen -t ed25519`生成密钥对，默认保存为`~/.ssh/id_ed25519`和`~/.ssh/id_ed25519.pub`，分别为私钥文件和公钥文件；如果使用RSA，则对应的默认文件名为`id_rsa`和`id_rsa.pub`。私钥可以设置口令保护；
- 把公钥文件的内容追加到服务端目标用户的`~/.ssh/authorized_keys`中，没有该文件时需要新建，已存在时不要覆盖原有内容。本步骤也可以通过客户端的`ssh-copy-id -i ~/.ssh/id_ed25519.pub 用户名@主机`完成；
- 更新`authorized_keys`通常不需要重启SSH服务。如果无法登录，应检查目标用户是否正确、服务端是否允许公钥认证，以及相关目录和文件的所有者与权限。常见设置为`~/.ssh`权限`700`、`authorized_keys`权限`600`，并确保其他用户不能写入这些文件；
- 公钥认证不要求输入远程用户的登录密码，但如果私钥设置了口令，客户端仍可能提示输入私钥口令，也可以使用`ssh-agent`管理已解锁的私钥；
- 如需禁止root登录或禁用密码认证，应先确认公钥认证能正常使用，再修改服务端配置；
- 对于脚本等非交互场景，可以提前通过可信渠道取得并配置主机公钥。`StrictHostKeyChecking=no`会自动接受未知主机公钥，降低主机身份校验的保障，不应把跳过确认等同于完成身份验证。
